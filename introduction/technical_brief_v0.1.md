# 技术简报：视觉追踪陪护台灯机器人

- 版本：0.1
- 日期：2026-09-02
- 项目主题：Companion Robot built on Raspberry Pi

## 1. 项目概述

本项目实现一台基于 Raspberry Pi 的桌面台灯机器人。机器人通过摄像头识别并持续追踪目标人物，驱动两轴 pan/tilt 机构使人物保持在画面中心；通过人体姿态的时间序列识别疑似跌倒状态；通过唤醒词进入语音交互模式，作为简短的伴聊机器人。OLED 屏幕持续显示时间、日期和天气等状态信息。

项目的核心不是单独运行 YOLO 或单独运行 LLM，而是把视觉感知、机械控制、语音交互、边缘计算和显示输出组织为一个可测量的实时系统。

## 2. v0.1 范围

### 2.1 本版本目标

1. 通过摄像头检测人体并持续追踪一个选定目标。
2. 根据目标在画面中的位置控制 pan/tilt 舵机，使其回到画面中心附近。
3. 从人体姿态关键点的连续轨迹中识别 `normal`、`suspected_fall` 和 `fallen` 三种状态。
4. 通过唤醒词启动麦克风录音、语音识别和本地 Qwen 0.5B 量化模型的短对话。
5. 通过 OLED 显示时间、日期、天气、网络状态、目标跟踪状态和跌倒事件状态。
6. 在疑似跌倒时暂停相机主动追踪，避免舵机运动造成画面模糊；提高姿态分析频率，并通过语音询问用户是否需要帮助。

### 2.2 本版本不包含

- 感光传感器和环境光自动调节。
- 陶瓷灯丝亮度自动控制。
- 医疗诊断、自动呼叫急救服务或对跌倒事件作出医疗可靠性承诺。
- 多目标长期身份识别。
- 将原始视频上传到云端。

感光与灯光亮度控制作为后续版本功能。届时 Raspberry Pi GPIO 仅输出 PWM/使能控制信号，陶瓷灯丝由独立的恒流驱动和外部电源供电。

## 3. 系统架构

```text
Camera Module 3
    -> person / pose inference
    -> target tracker
    -> PID pan/tilt controller

pose keypoint sequence
    -> temporal fall classifier
    -> event state machine
    -> OLED status + voice confirmation

microphone
    -> wake-word detector
    -> ASR
    -> local Qwen 0.5B (quantized)
    -> speaker

network
    -> weather service
    -> optional cloud dialogue extension
```

视觉实时链路和跌倒判定完全在本地运行。LLM 只接收结构化状态和用户语音转写，不参与实时控制或跌倒判定。天气服务只请求必要的地点和天气数据；原始摄像头画面默认不离开设备。

## 4. 关键技术方案

### 4.1 视觉追踪与主动相机控制

人体检测/姿态模型输出目标人物框和关键点。跟踪器在连续帧中维持目标 ID；由于相机会随 pan/tilt 机构移动，需采用支持相机运动补偿的跟踪方案。PID 控制器根据人物框中心与画面中心的偏差计算舵机角度。

当检测到快速下落、躯干角度异常或人物接近画面底部时，系统进入 `suspected_fall`：停止 pan/tilt 运动，并在固定画面中分析最近一段关键点序列。

### 4.2 跌倒事件识别

跌倒不能由单帧人体框的宽高比判断。系统将肩、髋、膝等关键点在短时间窗内的坐标、速度、躯干角度和人体高度变化输入轻量时序模型，例如 GRU 或 TCN。输出状态如下：

- `normal`：正常站立、行走、坐下或其他非危险活动。
- `suspected_fall`：出现快速下降或异常姿态，需要提高检测频率。
- `fallen`：异常状态持续满足阈值，需要进行语音确认。

`fallen` 只表示非医疗意义上的异常活动提醒。系统会优先语音确认，降低误报造成的打扰。

### 4.3 语音伴聊

唤醒词触发后，系统采集短语音并进行 ASR。语音转写和当前系统状态被送入本地量化的 Qwen 0.5B 模型，生成简短回答，再通过扬声器播放。复杂、长上下文对话可在后续版本接入云端 LLM，但不作为 v0.1 的必要依赖。

### 4.4 OLED 信息面板

OLED 通过 I2C 显示：

- 当前时间和日期；
- 天气摘要；
- Wi-Fi/网络状态；
- 视觉追踪状态；
- 跌倒事件状态；
- 语音交互状态。

## 5. 计划硬件

| 模块 | v0.1 用途 |
| --- | --- |
| Raspberry Pi 5 4GB | 本地视觉、语音、控制与显示主机 |
| Camera Module 3 标准视角版 | 人体追踪和姿态分析 |
| 两轴 pan/tilt 支架 + 两个舵机 | 主动调整相机视角 |
| PCA9685 | 舵机 PWM 驱动 |
| USB 麦克风与 USB 扬声器 | 语音交互 |
| I2C OLED，例如 SSD1306 128x64 | 状态显示 |
| 按钮 | 后续灯光模式切换与手动控制 |
| 官方 27W 电源 + Active Cooler | Raspberry Pi 稳定供电与散热 |

舵机使用独立 5V 电源；Raspberry Pi、舵机驱动和未来灯光驱动的 GND 必须共地。陶瓷灯丝不连接到 GPIO 供电端。

## 6. 软件模块边界

| 模块 | 职责 |
| --- | --- |
| `vision` | 相机采集、人体检测、姿态关键点和跟踪结果 |
| `pantilt` | PID 计算、舵机角度限制和追踪暂停 |
| `fall_detection` | 关键点缓存、时序分类和事件状态机 |
| `voice` | 唤醒词、ASR、本地 LLM、TTS |
| `display` | OLED 页面刷新和状态展示 |
| `weather` | 天气数据请求与缓存 |
| `main` | 模块调度、共享状态和启动入口 |

## 7. 验收指标

v0.1 完成时，系统应能够：

1. 在室内单人场景中持续将目标保持在画面中心区域。
2. 在站立、坐下、躺下和模拟跌倒场景中输出连续的活动状态。
3. 对 `suspected_fall` 和 `fallen` 事件在 OLED 上显示状态，并发起语音确认。
4. 由唤醒词启动一次简短本地中文问答。
5. 在 OLED 上稳定显示时间、日期和天气。
6. 记录端到端事件延迟、跟踪帧率、CPU 使用率、内存使用率和误报/漏报情况。

## 8. 后续版本
