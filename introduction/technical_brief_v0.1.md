# 技术简报：视觉追踪情绪支持台灯机器人

- 版本：0.1
- 日期：2026-09-08
- 项目主题：Companion Robot built on Raspberry Pi

## 1. 项目概述

本项目实现一台基于 Raspberry Pi 的桌面陪伴台灯机器人。机器人通过摄像头持续追踪正在交互的用户，驱动两轴 pan/tilt 机构将用户保持在画面中心；用户通过唤醒词启动语音交互，系统从已获授权的临床心理健康知识库中检索相关内容，并由本地量化的 Qwen 0.5B 模型生成简短、受约束的情绪支持回应。OLED 屏幕显示时间、日期、天气和系统状态。

本项目定位为非医疗的情绪支持、心理健康科普和陪伴交互系统，不提供精神疾病诊断、治疗方案或替代专业心理服务。核心研究问题是：如何在树莓派有限算力下，结合本地检索增强生成、隐私保护和安全边界，实现低延迟的语音陪伴交互。

## 2. v0.1 范围

### 2.1 本版本目标

1. 通过摄像头检测并持续追踪正在交互的单个用户。
2. 根据用户在画面中的位置控制 pan/tilt 舵机，使用户保持在画面中心附近。
3. 通过唤醒词启动麦克风录音、语音识别、本地知识库检索和本地 Qwen 0.5B 量化模型的短对话。
4. 在普通情绪困扰场景中，基于检索到的授权知识内容生成简短、尊重和非诊断性的回应。
5. 在检测到明显高风险表达时，停止开放式生成，输出固定的安全提示和专业支持建议。
6. 通过 OLED 显示时间、日期、天气、网络状态、视觉追踪状态和语音交互状态。
7. 记录本地检索、模型生成和端到端语音交互的延迟、内存与 CPU 使用率。

### 2.2 本版本不包含

- 跌倒监测、姿态风险判定和自动紧急呼叫。
- 医疗诊断、处方建议或治疗效果承诺。
- 多目标长期身份识别。
- 感光传感器和环境光自动调节。
- 陶瓷灯丝亮度自动控制。
- 将原始视频、原始语音或原始临床数据上传到云端或 GitHub。

感光与灯光亮度控制作为后续版本功能。届时 Raspberry Pi GPIO 仅输出 PWM/使能控制信号，陶瓷灯丝由独立的恒流驱动和外部电源供电。

## 3. 系统架构

```text
Camera Module 3
    -> person detector / tracker
    -> PID pan/tilt controller

microphone
    -> wake-word detector
    -> ASR
    -> safety screen
        -> high-risk: fixed safety response
        -> normal: local knowledge-base retrieval
                   -> local Qwen 0.5B (quantized)
    -> TTS -> speaker

network
    -> weather service
    -> optional cloud dialogue extension

OLED
    <- time / date / weather / system state
```

视觉追踪、唤醒词、语音预处理、知识库检索和安全筛查在本地运行。LLM 仅接收用户语音转写、检索片段和结构化状态，不负责高风险识别，也不控制机械机构。原始摄像头画面默认不离开设备。

## 4. 关键技术方案

### 4.1 视觉追踪与主动相机控制

人体检测模型输出正在交互用户的人体框，跟踪器在连续帧中维持目标。PID 控制器根据人体框中心与画面中心的偏差计算 pan/tilt 舵机角度。视觉模块只用于提升陪伴交互的具身感，不做用户身份识别，也不保存原始视频。

### 4.2 检索增强情绪支持对话

唤醒词触发后，系统进行 ASR，并从授权知识库中检索与用户表达相关的心理健康科普、情绪调节或沟通建议片段。Qwen 0.5B 依据固定系统提示词和检索片段生成简短回应。

本地模型的职责是组织语言和维持对话风格，而不是自行产生医学知识。v0.1 不对 Qwen 进行临床数据微调，避免模型记忆敏感内容；知识更新通过受控检索库完成。

### 4.3 安全边界

系统对明显的自伤、自杀、伤害他人或急性危险表达进行独立筛查。命中后不继续进行开放式“心理咨询”，而是以固定话术鼓励用户联系身边可信任的人、当地紧急服务或专业心理援助热线。安全处置文本、关键词和触发逻辑需由知识库授权方或具备相关资质的人员复核。

### 4.4 OLED 信息面板

OLED 通过 I2C 显示：

- 当前时间和日期；
- 天气摘要；
- Wi-Fi/网络状态；
- 视觉追踪状态；
- 唤醒词和语音交互状态；
- 本地检索与模型响应状态。

## 5. 临床知识库与 GitHub 数据管理

本项目使用的临床心理健康知识库具有明确使用授权。为保护数据主体隐私并遵守授权边界，数据按以下规则管理：

1. 原始临床数据、原始咨询记录、原始音视频、可重新识别的案例文本、身份映射表和访问密钥不得上传 GitHub。
2. 上传到 GitHub 的资料必须经过去标识化和语义泛化（模糊化）处理：删除直接身份标识符，处理精确日期、地点、职业和罕见事件等可能重新识别个体的信息。
3. 公开仓库仅保存代码、数据处理规范、检索接口、数据字段说明，以及经授权审核的去标识化派生样例或合成测试数据。
4. 每次新增数据前，先确认该材料的授权范围允许课程协作、代码仓库保存和论文实验；无法确认的材料不进入仓库。
5. Raspberry Pi 上仅保存完成项目所需的最小数据副本，并限制访问权限；测试日志不记录完整原始对话内容。

## 6. 计划硬件

| 模块 | v0.1 用途 |
| --- | --- |
| Raspberry Pi 5 4GB | 本地检索、语音、视觉、控制与显示主机 |
| Camera Module 3 标准视角版 | 交互用户追踪 |
| 两轴 pan/tilt 支架 + 两个舵机 | 主动调整相机视角 |
| PCA9685 | 舵机 PWM 驱动 |
| USB 麦克风与 USB 扬声器 | 唤醒词、语音输入和语音输出 |
| I2C OLED，例如 SSD1306 128x64 | 状态显示 |
| 按钮 | 后续灯光模式切换与手动控制 |
| 官方 27W 电源 + Active Cooler | Raspberry Pi 稳定供电与散热 |

舵机使用独立 5V 电源；Raspberry Pi、舵机驱动和未来灯光驱动的 GND 必须共地。陶瓷灯丝不连接到 GPIO 供电端。

## 7. 软件模块边界

| 模块 | 职责 |
| --- | --- |
| `vision` | 相机采集、人体检测和交互目标跟踪 |
| `pantilt` | PID 计算和舵机角度限制 |
| `wake_word` | 唤醒词检测 |
| `voice` | ASR、TTS 和对话状态管理 |
| `knowledge_base` | 本地向量检索、引用片段和数据访问控制 |
| `safety` | 高风险表达筛查和固定安全响应 |
| `llm` | 本地量化 Qwen 的受约束短文本生成 |
| `display` | OLED 页面刷新和状态展示 |
| `weather` | 天气数据请求与缓存 |
| `main` | 模块调度、共享状态和启动入口 |

## 8. 验收指标

v0.1 完成时，系统应能够：

1. 在室内单人交互场景中持续将用户保持在画面中心区域。
2. 由唤醒词启动一次本地中文语音问答。
3. 对普通情绪支持请求检索知识库片段，并生成与检索内容一致的短回应。
4. 对预定义高风险测试语句输出固定安全提示，而不是开放式生成回答。
5. 在 OLED 上稳定显示时间、日期、天气和交互状态。
6. 记录端到端响应延迟、检索命中率、CPU 使用率和内存使用率。
7. 验证 GitHub 中不包含原始临床数据、可识别案例、原始音视频或访问密钥。
